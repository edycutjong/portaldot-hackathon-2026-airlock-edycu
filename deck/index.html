README · Problem statement

The left card is our own control: the same thief script against a vault with delay zero moved 100 UNIT in a single extrinsic, on an interim chain. That is the default for anyone holding POT on one key. A multisig fixes it, but makes every payment a two-signature job.

The mechanism

Announce. Wait. Veto.

1 · hot key · delay 10

Announce

It cannot spend directly. It can only publish a call hash.

Proxy.announce
2 · 10 blocks ≈ 60 s on V3

Wait

The watcher alerts: YOURS, or NOT YOURS with the amount and a veto line.

event Proxy.Announced
3 · cold key · delay 0

Veto

The thief's execute then fails Proxy.Unannounced.

Proxy.reject_announcement

Your own spend: register the intent, announce, wait, execute. No co-signer.

Two keys, two roles. The hot key is registered with a delay, so the chain only lets it announce. The cold key has no delay and can reject any announcement as the vault. The watcher is what makes the window usable: it tells you which announcement is not yours, and prints the command to kill it.

How it is wired

The chain holds the ticket. Airlock reads it.

  • On chainThe Proxy pallet holds the delay and the veto. No contract, no custom runtime code.
  • Owner's machineWatcher, intent registry and CLI. The watcher never signs.
  • Before signingchain_profile.py checks genesis and runtime code hash.
This is the README diagram. The only enforcement is on chain: the Proxy pallet holds the delay and the veto. Everything we run is on the owner side and can fail without losing funds: a dead watcher means no alert, never a shorter delay.

Why it's new

The primitive existed. The product didn't.

Delayed proxies with announce and reject ship in the Proxy pallet. In our search (not a market survey) we found no product built on that path.

The new part is not a primitive, it is the product around one. The pallet already had announce and reject; what was missing is a vault layout that uses them, and a watcher that tells the owner which announcement to reject.

Ecosystem fit

Portaldot's Proxy pallet enforces it.

Proxy.create_purethe keyless vault
Proxy.add_proxyhot key with delay, cold key with 0
Proxy.announcethe hot key publishes a call hash
Proxy.proxy_announcedruns after the delay, if not vetoed
Proxy.reject_announcementthe veto
Proxy.remove_proxypanic: retire the hot key

Security is Portaldot's consensus: a compromised server can mislabel or drop an alert, but cannot move funds or shorten the delay.

Running on Portaldot V3 (portaldot-v3/3002) since 2026-10-19. No contract deployed.
Plan, not built: the hold-ticket flow inside Portaldot Wallet; Revive.call as a held call.

Remove Portaldot and the enforcement disappears: the Proxy pallet's calls and two storage maps are the core. That also means the trust model is the chain's. Our watcher and registry can be wrong or down; the delay and the veto are still enforced by consensus.
